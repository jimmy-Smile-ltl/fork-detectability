### 4. 数据结构设计

**要知道的**：为什么用统一信封、九态如何区分"没数据"和"没采到"。

| 内容 | 位置 |
|---|---|
| **统一信封**（8 个字段管 8 个维度） | [00 §4.1](00_项目总纲.md) |
| 落盘文件映射（唯一权威） | [00 §4.1.1](00_项目总纲.md) |
| **兼容层**（旧格式 → 新九态） | [00 §4.2](00_项目总纲.md) |
| 特征表设计（83 列） | [00 §4.3](00_项目总纲.md) |

**九态的关键区分**：

| Outcome | 含义 | payload |
|---|---|---|
| `OK` | 有数据 | 数据 |
| `EMPTY` | 资源存在但为空 | **值 0** |
| `DELETED` | 账号注销 | `None` |
| `NETWORK` | 没采到（可重试） | — |

**"EMPTY 是 0、DELETED 是 None"是本项目最贵的教训** —— 混成同一个 0 会让"零提交率"彻底失真。

| 文档 | 内容 | 适合 |

| [**11_指标手册**](11_真人判别指标手册.md) | **每个指标的计算公式 + 四仓实测值 + 判定** | 想实现的人 |
| [04_特征清单](04_特征清单.md) | 81 个可计算特征的目录 | 想扩展的人 |

### 7. 数据分析方案

**要知道的**：怎么从 20 万人走到"能下什么结论"。

| 内容 | 位置 |
|---|---|
| 两轴模型（身份自证 × 批量性，**禁止求和**） | [00 §5.1](00_项目总纲.md) |
| 三条分析路径（身份/行为/协调） | [00 §5.2](00_项目总纲.md) |
| 12 条判据的完整数值 | [00 §5.3](00_项目总纲.md) |
| **时间控制**（fork 龄分桶） | [00 §5.4](00_项目总纲.md) |
| **内部对照**（排除受众差异） | [00 §5.5](00_项目总纲.md) |
| 统计不确定性（Wald 区间） | [00 §5.6](00_项目总纲.md) |
| 六步判定流程 | [00 §5.7](00_项目总纲.md) |
| 21 个被证伪判据 | [00 §5.8](00_项目总纲.md) |
| 分析规范（L1–L5、复现纪律） | [analysis/README](../analysis/README.md) |

**三个必须遵守的纪律**：
1. **时间控制**：两仓 fork 龄差 8 倍，不能直接比
2. **内部对照**：同仓爆发窗内外对照，才能排除"受众差异"
3. **两轴不求和**：合成一个分数必然把两类信息搅成浆糊

**要知道的**：15 张图怎么画、有哪些坑。

→ [**15_图表与报告生成 §1–2**](15_图表与报告生成.md)

**五个技术约定**：
1. 中文字体必须显式设置（否则方块）
2. **CDF 的零值不能过滤**（否则曲线消失）
3. 象限图标签顺序必须与数据一致
4. 样本量必须标在图上
5. 颜色约定（红=rea，蓝=openclaw）

### 9. 分析报告生成

**要知道的**：从 JSONL 到最终报告的完整流程。

→ [**15_图表与报告生成 §3**](15_图表与报告生成.md)

**报告结构**（`02_图文报告.md`）：
```
序言 → 时间轴图 → 判据表 → 效应量排名 → 分布图 → 象限 → 时间控制 → 结论
```

**写作纪律**：
- 每个百分比带分母
- 异常 ≠ 造假（本报告全程不做定性）
- 不列入
- **证伪也要写**
- **记录自己的错**

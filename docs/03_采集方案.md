# 采集方案（最优设计版）

> **目标**：覆盖**全部维度**，且**请求数最少**。
> **版本**：2026-11-12 · 基于 6 天实测（19 万账户、约 40 万请求）
> **原则**：能数网页就不调 API；一次请求榨干页面；API 只留给网页拿不到的东西。

---

## 一、要采的全部维度（14 项指标）

| # | 指标 | 含义 | 用于哪根轴 |
|---|---|---|---|
| 1 | **fork 时间戳** | 谁在什么时候 fork | 批量性（最强） |
| 2 | **fork 后是否动过** | `pushed_at > created_at` | 行为真实性（最强） |
| 3 | 账户基本档案 | 名字/公司/位置/简介/注册时间 | 身份自证 |
| 4 | **star 总数** | 点过多少星 | 身份自证（消费宽度） |
| 5 | **自建 vs fork 结构** | 有没有自己的代码 | 身份自证 |
| 6 | **全年活跃日历** | 365 天逐日贡献 | 行为（最强） |
| 7 | **成就徽章** | Pull Shark 等 | **真实开发者硬证据** |
| 8 | 组织归属 | 属于哪些 org | 身份自证（弱） |
| 9 | 头像类型 | 默认 vs 照片 | 身份自证（已证伪） |
| 10 | 近 90 天事件 | Push/Watch/Fork 构成 | 行为 |
| 11 | watch 总数 | 订阅多少仓 | 消费宽度 |
| 12 | 自建仓的提交数 | 本人写了多少 commit | 行为（硬证据） |
| 13 | star 明细+时间 | 何时点了哪个星 | 行为（时序） |
| 14 | 社交图 | 关注/被关注名单 | **关系维度（未探索）** |

## 二、方法探索记录（全部试过，含失败）

这一节记录**每一个尝试过的通道和结论**，避免后来者重复踩坑。

### 2.1 API 通道

| 端点 | 请求 | 结果 | 结论 |
|---|---:|---|---|
| `/repos/{o}/{r}/forks` | 1/页 | ✅ 100/页，无页数上限 | **唯一完整身份通道** |
| `/users/{login}` | 1 | ✅ 15 字段 | 可用，但配额消耗大 |
| `/users/{l}/starred?per_page=1` | 1 | ✅ Link 尾页 = 总数 | 可用 |
| `/users/{l}/starred` + `star+json` | 1/页 | ✅ 含 starred_at | 可用但贵 |
| `/users/{l}/subscriptions` | 1 | ✅ watch 总数 | 可用 |
| `/users/{l}/orgs?per_page=100` | 1 | ✅ 组织列表 | 可用 |
| `/users/{l}/events/public` | 1–3 | ✅ 90 天 / ≤300 条 | 可用 |
| `/repos/{o}/{r}/commits?author=` | 1/仓 | ✅ Link 尾页 = 提交数 | 可用；空仓返回 **409**（不是失败） |
| `/users/{l}/repos?per_page=100` | 1–10 | ✅ 精确结构 | 可用但贵 |
| **`/repos/{o}/{r}/stargazers`** | — | ❌ **403→404（仅所有者可读）** | **拿不到** |
| **`/repos/{o}/{r}/subscribers`** | — | ❌ **同上** | **拿不到** |
| `/graphql` | — | ❌ 匿名 0 配额 | 不可用 |
| `/search/*` | — | ⚠️ 10 次/分钟 | 太慢，仅小规模 |

### 2.2 HTML / CDN 通道（不消耗 API 配额）

| 端点 | 请求 | 能拿到 | 实测 |
|---|---:|---|---|
| `github.com/{login}` | 1 | **star 数、仓数、成就、组织、关注数、pinned、名字** | ✅ 一次 7 个字段 |
| `github.com/{login}?tab=repositories` | 1–3 | 自建 vs fork 结构 | ✅ 二分类 **96%** vs API |
| `github.com/{login}?tab=stars` | 1 | star 条目数 | ❌ **浪费**——个人主页已有 star 数 |
| `github.com/users/{l}/contributions` | 1 | 365 天逐日贡献 | ✅ 99.2% |
| `github.com/{login}.atom` | 1 | **最近 30 条事件类型** | ✅ 可用（RSS） |
| `avatars.githubusercontent.com/u/{id}` | 1 HEAD | 头像大小 → 类型 | ✅ 精确 |
| `github.com/{login}?tab=followers` | 1/页 | 关注者名单 | 未做（P1） |

### 2.3 关键实测数字

| 项 | 值 | 说明 |
|---|---|---|
| API 硬顶 | **60 次/小时/IP** | 按 IP，不按端点 |
| 快代理有效供给 | 55 次/分钟（满额时） | 加线程无效，瓶颈在 IP 数 |
| Clash 共享订阅的 API 配额 | **0**（98 个节点全为 0） | 被别人打满，只能跑 HTML |
| Clash HTML 吞吐 | **190–400 人/分钟** | 单出口，多进程会互相挤 |
| 直连 HTML | 5,000 次后**被风控掐断** | 不能长期直连 |
| 头像 CDN 直连 | **1,300 人/分钟** | 无风控，最快通道 |
| HTML 页面的风控 | 软限流，无小时计数 | 400/分钟没事 |

## 三、最优方案：每人 5 个免费请求

### 3.1 核心设计

```
每人 5 个请求，全部走 HTML/CDN，API 配额消耗 = 0

①  github.com/{login}                               → star数 + 仓数 + 成就 + 组织 + 关注数
②  github.com/{login}?tab=repositories              → 自建 vs fork 结构
③  github.com/users/{login}/contributions?from=&to= → 365 天逐日活跃
④  avatars.githubusercontent.com/u/{id}   (HEAD)    → 头像类型
⑤  github.com/{login}.atom                          → 最近 30 条事件类型
```

### 3.2 这 5 个请求覆盖了什么

| 维度 | 覆盖情况 | 精度 |
|---|---|---|
| 3 基本档案 | ✅ 部分（名字/简介/位置/公司/关注数） | 够用（精确值得靠 D1，已有 96%） |
| 4 star 总数 | ✅ **完全** | **精确**（如 tj = 2,311） |
| 5 自建 vs fork | ✅ 完全 | 二分类 96% |
| 6 全年日历 | ✅ 完全 | 99.2% |
| 7 成就徽章 | ✅ **完全** | 精确 |
| 8 组织归属 | ✅ **完全** | 精确 |
| 9 头像类型 | ✅ 完全 | 精确 |
| 10 事件类型 | ⚠️ 最近 30 条 | 够看类型构成 |
| 1 fork 时间戳 | ✅ 随 fork 名单返回 | 精确（**0 请求**） |
| 2 fork 后动过 | ✅ 同上 | 精确（**0 请求**） |

**10 / 14 个维度只靠免费通道就能拿到，其中 2 个维度连请求都不需要。**

### 3.3 剩下 4 个维度必须用 API

> **2026-11-12 用户决策**：watch 数「意义不大，靠后」；
> **提交数（D9）和 star 明细+时间（D4L）「意义很大，都需要采集」**。

| 维度 | 端点 | 请求/人 | 优先级 | 为什么不能用 HTML |
|---|---|---:|---|---|
| **12 自建仓提交数** | `/repos/{o}/{r}/commits?author=` | 1–3 | **P1（用户指定要）** | 网页不显示"某人贡献了几个 commit" |
| **13 star 明细+时间** | `/starred` + `star+json` | 1–4 | **P1（用户指定要）** | 网页不显示点星时间 |
| 11 watch 总数 | `/subscriptions` | 1 | **P4（靠后）** | 网页无 watch 入口 |
| 4' star 数 >30 的精确值 | `/starred?per_page=1` | 1 | P3（可选） | HTML 分页上限 |

### 3.3.1 省下来的两个维度（重要）

| 维度 | 原计划 | 现在 | 省下 |
|---|---|---|---|
| **4 star 总数** | API `/starred` 19 万 | **HTML `Counter[3]`**（tj = 2,311 精确） | **19 万** |
| **8 组织归属** | API `/orgs` 19 万 | **HTML `avatar-group-item`**（tj 有 13 个 org） | **19 万** |

**合计省下 38 万 API 请求**——因为个人主页一次就带这两项。

### 3.4 请求预算（19 万人）

| 方案 | 免费请求 | API 请求 | 总请求 |
|---|---:|---:|---:|
| 旧方案（每维度一次 API） | — | **1,910,000** | 1,910,000 |
| **最终方案（用户指定：D9 + D4L 必采，watch 靠后）** | **954,570** | **660,000** | 1,564,570 |

**API 部分明细**：

| 维度 | 请求 | 说明 |
|---|---:|---|
| D9 自建仓提交数 | ~280,000 | 只有"有自建仓"的约 14 万人，每人 2 个仓 |
| D4L star 明细 | ~380,000 | 按 star 数分页，中位数小，多数 1 页 |
| **合计** | **660,000** | 按 3,300/h ≈ **200 小时 ≈ 8.3 天** |

## 七、一句话总结

> **一个人的全部画像，5 个免费请求就够。**

### P1-2　采样 5,000 人并采集

# 应改为随机采样，见 P1-3）
py scripts/collect/collect_loop.py \
  --repo ollama/ollama --mode per_account \
  --dims D1,D14,D4L,D2B,D8H,D9 \
  --workers 20 --batches 40 --batch-seconds 280

### P1-3　⚠️ 需要先补一个小功能：随机采样

当前 `--limit N` 取的是**名单前 N 个**（按 fork 时间最早），不是随机。
这会让样本偏向"最早来的 forker"。

**需要改**：给 `collect_run.py` 加 `--sample N`（随机种子固定），或在采集前先打乱名单。

```python
import random
random.seed(42)
logins = random.sample(logins, min(N, len(logins)))
```

**这是 P1 的前置任务，约 10 分钟。**

## P2：D15/D13 慢速补采（~10 小时，可夜间跑）

### 问题

`github.com` 有软反爬：连续抓 5–8 页就封一段时间。
实测：单请求 200（2–4 秒），但**2 并发 75%、4 并发 38%、32 并发 0%**。

### 方案：1–2 并发 + 每请求间隔

```bash
# BettaFish（7,688 人）
py scripts/collect/collect_loop.py \
  --repo 666ghj/BettaFish --mode per_dim \
  --dims D15,D13 --workers 2 --batches 100 --batch-seconds 300
```

| 目标 | 人数 | 2 并发预计 |
|---|---:|---:|
| BettaFish D15+D13 | 7,688 | **~6 小时** |
| shardeum D15+D13 | 716 | ~35 分钟 |
| union D15+D13 | 4,297 | ~3.5 小时 |
| anoma D15+D13 | 4,139 | ~3.2 小时 |
| **合计** | 16,840 | **~13 小时** |

**判断**：D15 类判据（Pull Shark / 协作徽章）在本研究里**本来就是弱判据**
（rea 30.8% vs openclaw 40.5%，只能算 −9.7pp），
**P2 的收益远低于成本**。

**建议**：只补 **shardeum（35 分钟）**，让对照组至少有 D15 数据；
其余跳过，在报告里标注"该判据在三仓不可检验"。

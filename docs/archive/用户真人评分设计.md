# 用户真人评分设计（S5 阶段方案）

> ⚠️ **2026-11-05 修订提示**：本文的负向证据表（「三零形态 −20 / 孤岛形态 −15 / 空档新号 −10」）
> **已被实证推翻**——2,700 个真实 forker 里 30% 档案全空、0 粉 0 关在爆发窗反而更少（35% vs 47%）。
> 现行口径见 [`账户分析方案.md`](账户分析方案.md)：空档案只能算「无信息」，不能作为负向证据。
> 本文保留作设计留档，**实施请以后者为准**。

> 设计日期：2026-10-24 · 前置文档：`数据采集方案.md`（通道实测与合规框架）
> 目标：为每个账号输出**"活跃真人特征"置信度**（0–100 分 + 1–9 档），不是 0/1 判定，不下"造假"结论。
> 硬约束不变：全匿名、不登录、只读公开 API、限流纪律。

## 一、口径：这个分数到底在测什么

**"真人分数" = 账号表现出持续、多维度、像人类行为模式特征的强度。**

三条口径纪律（先说清楚，防止过度解读）：

1. **高分 ≠ 清白**：买了养号多年的老账号去刷 star，真人分数是 9 —— 所以真人分数**必须**与"行为可疑度"（时间聚集、爆发窗参与）交叉成二维矩阵才是最终分析形态（见第六节）。
2. **低分 ≠ 有罪**：注册了从不活动的潜水真人会落在 3–5 档；分数只描述"证据强度"，不描述动机。
3. **个体不点名，报告只出分布**：按群体（fork 群体 / CH star 样本 / 对照仓群体）对比分布差异。

## 二、采集字段清单（核心 4 req/人）

| # | 端点 | 字段 | 判别用途 | 成本 |
|---|------|------|---------|------|
| D1 | `GET /users/{login}` | `type` | Bot/Organization 直接分流，不进真人评分 | 1 |
| | | `created_at` | **账号年龄**：最硬的单一信号。养号成本随年份指数上升 | |
| | | `public_repos` `public_gists` | 内容生产量（含 fork 仓，粗口径） | |
| | | `followers` `following` | 社交图谱密度；0/0 是幽灵号典型形态 | |
| | | `company` `location` `blog` `email` `bio` `hireable` | **档案完整度**：每项都要人花时间填；批量号几乎全空 | |
| | | `updated_at` | 档案最近变动（弱信号） | |
| D2 | `GET /users/{login}/events?per_page=100` | 事件总数、时间跨度 | 90 天内**有没有行为** | 1 |
| | | **类型分布** | `PushEvent`/`CreateEvent`/`PullRequestEvent` = 开发行为（真人铁证级）；纯 `WatchEvent` = 挂机；0 条 = 幽灵 | |
| | | 活跃天数 | 90 天里有行为的天数（节奏持续性） | |
| | | 周内/小时内分布 | 真人有作息节律，机器均匀（次级特征） | |
| D3 | `GET /users/{login}/starred?per_page=1&sort=created` | Link 尾页 = **star 总数** | 潜水真人也会 star（几十~几千）；批量号常为 0–5 | 1 |
| D4 | `GET /users/{login}/orgs` | 组织列表 | 真人常挂 org（公司/开源组织） | 1 |

| 字段 | 实证小号样本（本地私有名单） | mneves75（普通真人，fork 样本） | steipete（仓库作者） |
|---|---|---|---|
| 注册 | 2026-06（4 个月） | 2012（14 年） | 2009（17 年） |
| repos | **0** | 85 | 227 |
| followers | **0** | 32 | 53,370 |

→ 三档在几乎每个字段上都拉开距离，判别空间充足。

## 三、免费旁证（已在手，0 请求）

1. **fork 行为数据**（`probe_forks_all.jsonl`，82,176 条）：同一 login 的 `fork_touched`（fork 后是否推送过）、`fork_created_at` 与账号注册时间的间隔（**注册 <30 天就 fork 爆发仓 = 强可疑**）、`owner_type`。
2. **CH star 时间戳**（105,696 actor）：该账号点星是否落在同秒批量批里（批量批成员 = 行为可疑，与真人分数独立）。
3. **404 探测本身**：`/users/{login}` 返回 404 = 账号已删/被封 —— **fork 后账号消失**本身就是垃圾账号信号，单独记一类（"已蒸发账号率"）。

## 四、评分框架（证据累加制，非加权平均）

采用**正向证据加分 + 负向证据扣分**的累加制，每项独立可解释，总分 clamp 到 0–100。

### 正向证据（上限 +105）

| 证据 | 条件 | 分值 |
|---|---|---:|
| 账号年龄 | ≥5 年 +25 · ≥2 年 +18 · ≥1 年 +10 · ≥6 个月 +5 | +0~25 |
| 开发行为（90 天事件） | Push≥10 条 +20 · 有 Push +12 · 有非 Watch 事件 +8 · 仅 Watch +3 · 0 条 +0 | +0~20 |
| 活跃持续性 | 活跃天数 ≥20 +10 · ≥5 +5 | +0~10 |
| 自有仓库 | ≥10 个 +12 · ≥1 个 +6 | +0~12 |
| star 消费行为 | ≥50 +8 · ≥5 +4 | +0~8 |
| 社交：followers | ≥10 +8 · ≥1 +4 | +0~8 |
| 社交：following | ≥5 +4 · ≥1 +2 | +0~4 |
| 组织成员 | ≥1 个 org +6 | +0~6 |
| 档案完整度 | bio/company/location/blog/email 每项 +2（上限 +8） | +0~8 |
| fork 后有推送 | `fork_touched=1`（自家数据）+10 | +0~10 |

### 负向证据（上限 -60）

| 证据 | 条件 | 分值 |
|---|---|---:|
| 短命账号 | 注册至可疑行为 <30 天 | -15 |
| 三零形态 | 0 事件 ∧ 0 repos ∧ 0 starred | -20 |
| 孤岛形态 | 0 repos ∧ 0 followers ∧ 0 starred | -15 |
| 批量时间戳 | 点星落在 CH 同秒批（≥2 人同秒） | -20 |
| 空档新号 | 档案全空 ∧ 注册 <90 天 | -10 |

### 档位映射（1–9）

| 档 | 分数 | 解读 |
|---|---|---|
| 1 | 0–10 | 幽灵号（三零/孤岛形态） |
| 2 | 11–20 | 高置信非活跃非真人特征 |
| 3 | 21–30 | 疑似占位号 |
| 4 | 31–40 | 偏假但证据有限 |
| 5 | 41–50 | **证据不足**（新号但合理 / 老号但零信息）——诚实保留 |
| 6 | 51–60 | 偏真（有基础消费行为） |
| 7 | 61–75 | 疑似真人（有生产行为或社交） |
| 8 | 76–90 | 高置信真人（多年 + 持续活动） |
| 9 | 91–100 | 铁证真人（多年 + 高强度开发 + 完整社交） |

## 五、校准方案（权重不是拍脑袋）

锚点组先跑，权重调整到锚点落位正确为止：

| 锚点 | 期望档位 |
|---|---|
| steipete、知名贡献者 5–10 人 | 8–9 |
| mneves75 等早期 fork 真人样本 | 6–8 |
| 实证小号样本 3 个（本地私有名单） | 1–2 |
| 随机老号（2015 年前注册、无活动） | 4–6（校准"潜水真人"不误伤） |
| 对照仓（vscode/react）CH 样本随机 50 人 | 分布主体应在 6–9 |

校准通过后才对全样本出分。**每次权重调整重跑锚点**（脚本化，防手滑）。

## 六、最终分析形态：真人分数 × 行为可疑度 二维矩阵

```
                 行为可疑度低              行为可疑度高（爆发窗/同秒批）
真人分数高   │ 正常开发者/粉丝        │ ★ 养号老账号参刷（最有情报价值的象限）
真人分数低   │ 潜水真人/新号          │ 批量注册小号（刷量主力）
```

报告核心输出 = 四象限占比，在 fork 群体 / CH star 群体 / 对照仓群体间对比。**单看任何一维都会误判**，二维交叉才有结论。

## 七、规模与成本（待用户拍板）

| 方案 | 人数 | 请求数 | 匿名直连耗时 | 说明 |
|---|---|---|---|---|
| 精简 | 600 | 2,400 | ~40 h（后台 2–3 天） | P0 同秒批全采 + P1 CH 新号 + P2 爆发窗 fork 抽样 + P3 早期 fork 对照 + P4 锚点 |

输出：`data/raw/user_profiles.jsonl`（每人一条，含全部原始字段+评分+档位+证据明细）→ `data/out/user_score_report.md`（分群体分布 + 二维矩阵）。

## 八、边界情况处理

| 情况 | 处理 |
|---|---|
| `type=Bot` | 不进真人评分，单独统计"fork 里有几个 bot" |
| `type=Organization` | 同上 |
| 404（已删/被封） | 记"蒸发账号"类，群体统计蒸发率（本身是信号） |
| 事件 100 条只覆盖最近几天 | 正常（活跃账号）；"活跃天数"按实际窗口折算 |
| 买了的老号 | 单维无法识别 → 交给二维矩阵的行为可疑度维度 |
| 潜水真人落在 3–5 档 | 报告措辞用"非活跃/低证据"，绝不用"假号" |

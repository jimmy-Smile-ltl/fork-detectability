## 1. D1 — 档案

```
GET https://api.github.com/users/{login}
成本：1 请求
```

**落盘字段（15 个 + 1 个布尔）**

| 字段 | 类型 | 含义 |
|---|---|---|
| `user_id` | int | 全局唯一 ID（**注册批次指纹**：ID 相邻 = 注册时间接近） |
| `type` | str | `User` / `Organization` / `Bot` |
| `name` | str | 昵称（可空） |
| `company` | str | 公司（可空） |
| `blog` | str | 个人网站（可空） |
| `location` | str | 位置（可空） |
| `hireable` | bool | 是否求职中 |
| `bio` | str | 简介（可空） |
| `twitter_username` | str | 推特（可空） |
| `public_repos` | int | **公开仓总数（含 fork）** |
| `public_gists` | int | gist 数 |
| `followers` | int | 粉丝数 |
| `following` | int | 关注数 |
| `created_at` | ISO | **注册时间** |
| `updated_at` | ISO | 档案最后修改时间 |
| `has_email` | bool | **只落布尔**（项目纪律：不存邮箱明文） |

**由它派生的指标**
- `account_age_days` = now − created_at
- `age_at_fork_days` = fork 时间 − created_at（**注册后多久来 fork 的**）
- `profile_filled` = name/bio/blog/location/company/twitter 里有值的个数（0–6）
- `profile_shape` = `EMPTY`(0) / `TEMPLATE`(恰好 name+location) / `RICH`(≥4) / `PARTIAL`(其余)

**坑**
- 404 = 账号已删/改名，**本身是信号**（记录为 `gone`，不再重试）
- `public_repos` 含 fork，**不能当"自建仓数"用**（要 D8）

## 2. D2 — 近 90 天活动

```
GET https://api.github.com/users/{login}/events/public?per_page=100&page=N
成本：1 请求/页（默认 1 页；上限 300 条/90 天）
```

**落盘字段（7 个）**

| 字段 | 类型 | 含义 |
|---|---|---|
| `events_total` | int | 抓到的事件总数（≤300） |
| `by_type` | dict | `{"WatchEvent": 120, "PushEvent": 3, ...}` |
| `dev_events` | int | **开发类事件数** = Push + PullRequest + Issues + IssueComment + Create + Release |
| `watch_events` | int | 纯点星数（`WatchEvent`） |
| `distinct_repos` | int | 事件涉及的去重仓库数 |
| `first_at` | ISO | 最早一条事件时间 |
| `last_at` | ISO | 最晚一条事件时间 |

**能回答什么**
- `dev_events == 0` 且有事件 → **只挂机不开发**
- `events_total == 0` → 近 90 天**完全静默**（僵尸号？还是真人不活跃？需结合 D13）
- `last_at` 距 fork 时间多远 → **是不是"被唤醒"**

**坑**
- API 只保留 **90 天**、最多 **300 条**，超出会截断（高活跃账号会被低估）
- 必须用 `/events/public`，`/events` 含私有事件，匿名访问会缺

## 3. D3 — 仓总数 + 最近 push

```
GET https://api.github.com/users/{login}/repos?per_page=1&sort=pushed
成本：1 请求
```

**落盘字段（3 个）**

| 字段 | 类型 | 含义 |
|---|---|---|
| `repos_total` | int | 仓总数（从 `Link: rel="last"` 的页码取，`per_page=1` 时页码 = 总数） |
| `newest_push` | ISO | **最近一次 push 的时间**（`sort=pushed` 的第 1 条） |
| `newest_push_repo` | str | 那个仓的 `full_name` |

**注意：`repos_total` 与 D1 的 `public_repos` 重复。** D3 的独有价值只有一个：`newest_push`。
所以**如果只想要活跃度，D3 值得采；如果已经有 D1，D3 不是必须的**。

**坑**
- `sort=pushed` 按 **pushed_at** 排序，不是 created_at
- 空仓（无 push）的 `pushed_at` 等于创建时间，会让人误判为"最近活跃"

## 4. D4 — star 总数（消费宽度）

```
GET https://api.github.com/users/{login}/starred?per_page=1
成本：1 请求
```

**落盘字段**：`starred_total`（int，star 仓数量）

**为什么重要**：真人的 star 数是几十到几千；**刚注册的批量号通常 0–个位**。
但注意：**老号刷量时这个值也很正常**（我们实测：同秒簇账号与普通 forker 的 star 分布无差异）。

## 5. D4L — star 明细（含时间戳）

```
GET https://api.github.com/users/{login}/starred?per_page=100&page=N
Header: Accept: application/vnd.github.star+json
成本：1 请求/页
```

**落盘字段**：`items`（`[{repo, at}]`）、`sampled`（页数×100 的采样上限）

**用途**：把 star 行为摊在时间轴上 → **`SAAR`（star 活动对齐率）**、
"fork 当天有没有同时点星"。

**坑**：不加那个 Accept 头，返回只有 repo 对象、**没有 `starred_at`**。

## 9. D8 — 仓库结构（自建 vs fork）★最强身份信号

```
GET /users/{login}/repos?per_page=100&sort=pushed&page=N
成本：1–10 请求/人（页数由 public_repos 决定，上限 1000 仓）
```

**落盘字段（13 个）**

| 字段 | 含义 |
|---|---|
| `sampled_repos` | 实际翻了多少个仓 |
| `fork_count` | 其中 fork 的数量 |
| `own_count` | **自建仓数量**（`fork == false`）★ |
| `own_empty` | 自建仓里 size=0 的空仓数 |
| `own_touched` | 自建仓里有 push 过的数量★ |
| `own_newest_push` | 自建仓里最近一次 push |
| `fork_newest_push` | fork 仓里最近一次 push |
| `own_details` | 前 20 个自建仓明细（name/size/pushed） |
| `fork_details` | fork 仓明细（含 **moved 标记**） |
| `has_profile_repo` | 是否有 `<login>/<login>` 个人主页仓★ |
| `repos_complete` | **是否翻完了全部仓**（1 = `own_count` 精确；0 = 只是采样值） |
| `pages_used` | 实际用了几页 |
| `repos_total_hint` | D1 报告的 `public_repos` |

**为什么最强**：`public_repos` 含 fork，所以"这个人有没有自己的作品"**只能靠 D8**。
实测（50 人样本）：`own_count == 0` 占 **28%**。

**铁律**：`own_count == 0` **只有在 `repos_complete == 1` 时才成立**——
仓超过 1000 个的账号翻不完，`own_count` 是采样值，不能当 0 读。

## 12. D13 — 年度贡献日历（0 API 配额）★

```
GET https://github.com/users/{login}/contributions?from=YYYY-01-01&to=YYYY-12-31
成本：0 API 配额（HTML 层）
```

**落盘字段**：每一天的 `date` + `count` + `level`（365 格）

**派生的最强指标**

| 指标 | 定义 | 为什么强 |
|---|---|---|
| `ACTIVE_DAYS` | 年内有贡献的天数 | 真人几十~几百；僵尸号 0–1 |
| `SINGLE_ACTION_YEAR` | 全年只有 1 天有贡献 | **16 岁号 + 全年 1 天 = 被唤醒** |
| `ACTION_ALIGNED` | 那唯一的一天是不是 fork 当天 | 直接指向"为这个动作而生" |

**实测 5 个账号**：
- `1733268368`：全年 **1 天 1 次贡献，就在 fork 当天**
- `saulnhodges`：全年 **1 天 1 次，在注册当天**

**坑**：一次只能请求**一整年**，不支持单月（`from`/`to` 都是年边界）。

## 13. D14 — 头像（0 API 配额）

```
HEAD https://avatars.githubusercontent.com/u/{id}?v=4
成本：0 API 配额
```
**落盘字段**：`status` `type`(`identicon`/`photo`/`gravatar`) `bytes`
**判据**：先 HEAD 看 `Content-Length`，再按大小阈值解码，**只做正向判断**
（"像照片" ≠ "是真人"）
**实测（50 人）**：identicon 50% / 真人照片 50% —— **几乎没有区分力**。

### 16.4 时间预算结论

```
现在 → 11-14 剩余约 105 小时（按 3,300 请求/小时 ≈ 34.6 万请求）

P0（44k）  + P1（190k） = 234k 请求 ≈ 71 小时   ← 做得到，且能出结论
再加 P2（380k）        = 614k 请求 ≈ 186 小时  ← 做不到
```

**所以现实方案是：P0 + P1 + 抽样 P4/P5**（约 75 小时），
把 D8 的精确值**留作 50 人样本估计**，并显式标注它不能外推。
